# Database

PostgreSQL 16 accessed through Prisma 7 with the `@prisma/adapter-pg` driver adapter. The schema is in `prisma/schema.prisma`; the generated client is written to `src/generated/prisma` (git-ignored, regenerated by `pnpm install` and `pnpm prisma:generate`).

## Conventions

- **Primary keys** are UUIDs (`@db.Uuid`, generated by Prisma/`randomUUID`).
- **Money** is stored as integers in minor units (`*Minor`: pence, cents). Tax rates and percentage discounts are basis points (`taxRateBps`, `discountValue` for `PERCENT`; 1000 = 10%). Quantities are `Decimal(12,3)`.
- **Timestamps** are UTC `DateTime`; most tables have `createdAt`/`updatedAt`.
- **Tenant isolation**: every tenant-owned table has `workspaceId` with `onDelete: Cascade` from `Workspace`, and composite indexes lead with `workspaceId`.
- **Soft deletion** is used where history matters (`Quote.deletedAt`, `StoredObject.deletedAt`, `User.deletedAt`, `Customer.archivedAt`).
- **Secrets are never stored in clear**: public quote links, invitations and local signed URLs store only SHA-256 hashes; IPs are stored as salted hashes (`ipHash`).
- Better Auth tables are mapped to lower-case names (`user`, `session`, `account`, `verification`); the rest use Prisma's default model names.

## Connection

`src/lib/db/prisma.ts` creates one `PrismaClient` with a `PrismaPg` pool (`max` 10 in production, 5 otherwise) and caches it on `globalThis` outside production. `DATABASE_URL` is the only connection string used at runtime; `DIRECT_URL` is validated but currently reserved for future pooled/direct splits.

## Model groups

### Authentication (Better Auth)

| Model | Purpose |
| --- | --- |
| `User` | Identity plus application fields: `platformRole` (`USER`, `SUPPORT_ADMIN`, `SUPER_ADMIN`), `suspendedAt`, `onboardingCompletedAt`, `lastLoginAt`, `deletedAt`, `locale` |
| `Session` | Database-backed sessions (token, expiry, IP, user agent) |
| `Account` | Credential provider record (hashed password) |
| `Verification` | Email verification, password reset and magic-link tokens |

### Workspaces (tenants)

| Model | Purpose |
| --- | --- |
| `Workspace` | Tenant: `name`, unique `slug`, `ownerId`, `status` (`ACTIVE`, `SUSPENDED`, `PENDING_DELETION`), `isDemo`, `aiCreditBalance`, deletion timestamps |
| `WorkspaceMember` | Membership with `role` (`MEMBER`, `ADMIN`); unique per user/workspace |
| `WorkspaceInvite` | Pending invitations: hashed token, role, expiry, status |
| `BusinessSettings` | One per workspace: business identity, address, currency, tax mode/label/rate, pricing mode, labour rate, call-out fee, terms, validity days, quote number prefix, logo, brand colours |
| `QuoteCounter` | Per workspace and year sequence for quote numbers |

### Customers and catalogue

| Model | Purpose |
| --- | --- |
| `Customer` | Individual or company, billing and job addresses, preferred contact method, internal notes |
| `CustomerTag`, `CustomerTagAssignment` | Free-form tags |
| `ServiceCatalogueItem` | Priced services and materials (`unit`, `kind`, `unitPriceMinor`, `internalCostMinor`, `taxTreatment`) |
| `QuoteTemplate` | Per-workspace wording templates (scope, inclusions, exclusions, assumptions, terms, questions) |
| `TradeTemplate` | Platform-level trade presets used at onboarding and by the marketing templates page |

### Quotes

| Model | Purpose |
| --- | --- |
| `Quote` | Header: number, status, customer, template, job address, captured enquiry inputs (`enquiryText`, `jobNotes`, `transcript`, `aiAnalysis`), current version pointer, public link fields (`publicTokenHash`, `publicTokenVersion`, `publicTokenExpiresAt`), lifecycle timestamps, `viewCount`, `pdfObjectId`, `totalMinor`, `wizardStep` |
| `QuoteVersion` | Immutable-once-locked snapshot of wording, pricing settings and totals; `versionNumber` unique per quote |
| `QuoteItem` | Line items of a version (description, customer description, quantity, unit, price, discount, tax treatment, internal cost, optional/AI flags) |
| `QuoteMedia` | Attached images, audio and documents referencing `StoredObject`, with transcript/AI description |
| `QuoteEvent` | Timeline (`CREATED`, `AI_ANALYSIS`, `SENT`, `VIEWED`, `ACCEPTED`, `REMINDER_SENT`, ...) with actor type and hashed IP |
| `QuoteAcceptance` | Customer decisions with signed name, terms flag, reason, total at the time |

Status enum: `DRAFT`, `READY`, `SENT`, `VIEWED`, `ACCEPTED`, `DECLINED`, `EXPIRED`, `ARCHIVED`. Allowed transitions are defined in `src/lib/quotes/status.ts`.

### Storage

| Model | Purpose |
| --- | --- |
| `Upload` | Pending/complete upload handshake records (`objectKey`, expected/actual bytes, purpose, expiry) |
| `StoredObject` | Finalised objects: key, bucket, purpose, MIME, size, dimensions, checksum, soft delete |
| `StorageUsageSnapshot` | Daily per-workspace and platform totals recorded by the cron job |

### Email

| Model | Purpose |
| --- | --- |
| `EmailTemplate` | One row per `EmailKind` (subject, preview text, Markdown body, allowed variables, enabled) |
| `EmailEvent` | Every send attempt with status (`SENT`, `PREVIEW`, `FAILED`, `SKIPPED`, ...), provider id, error and, in preview/test mode, the rendered HTML/text |

### Billing

| Model | Purpose |
| --- | --- |
| `Plan`, `PlanEntitlement` | Catalogue of plans (`FREE`, `STARTER`, `PRO`, `CREDIT_PACK_5`) with prices, allowances, limits, Stripe price ids and feature entitlements |
| `Subscription` | One per workspace: plan, status, interval, Stripe ids, period, cancellation, trial, complimentary access, last payment failure |
| `BillingInvoice` | Mirror of Stripe invoices |
| `CreditLedgerEntry` | Append-only ledger of credit grants and consumption with `idempotencyKey` |
| `UsageRecord` | Per-period counters (`AI_GENERATION`, ...) unique on workspace/metric/period start |
| `StripeWebhookEvent` | Idempotency and audit record for every received Stripe event |

### AI

| Model | Purpose |
| --- | --- |
| `AiPromptVersion` | Versioned system prompt and user template per feature; exactly one published |
| `AiRun` | Every provider call: feature, provider, model, prompt version, status, error category, tokens, audio seconds, estimated cost, credit flag |

## Migrations

Migrations live in `prisma/migrations` and are applied with:

| Environment | Command |
| --- | --- |
| Development | `pnpm db:migrate` (`prisma migrate dev`, creates a migration when the schema changed) |
| Production | `pnpm db:deploy` (`prisma migrate deploy`) — on Railway this runs as the pre-deploy command `./docker/entrypoint.sh migrate` |
| Tests | `tests/global-setup.ts` runs `prisma migrate deploy` against `TEST_DATABASE_URL` |

Workflow for a schema change:

1. Edit `prisma/schema.prisma`.
2. `pnpm db:migrate --name describe_change` (or plain `pnpm db:migrate` and answer the prompt).
3. Commit the new folder under `prisma/migrations` together with the schema.
4. Deploy; the pre-deploy command applies it before the new container receives traffic.

Never edit an applied migration. Prisma refuses to run in production when the migration history diverges.

## Seeding

`prisma/seed.ts` (run by `pnpm db:seed`, and by `pnpm db:reset` after a reset):

1. `seedPlatform` — upserts plans (create-only for existing rows so admin edits survive), entitlements, trade templates (create-only), prompt version 1 per feature (only when the feature has no version), email templates (upsert; the `variables` list is refreshed), feature flags (name/description refreshed, enabled state preserved).
2. `seedDemoWorkspace` — only when `DEMO_MODE=true` or `SEED_DEMO=true`. Deletes and recreates the demo workspace and user, so it is safe to repeat.
3. Promotes `SUPER_ADMIN_EMAIL` if that user exists (audit-logged with actor `seed`).

Production is **never** seeded automatically by the deploy pipeline. Run `pnpm db:seed` deliberately from a Railway shell or one-off command after the first deployment.

## Useful queries

```sql
-- Workspaces and their plan
SELECT w.name, p.key, s.status, s."currentPeriodEnd"
FROM "Workspace" w JOIN "Subscription" s ON s."workspaceId" = w.id JOIN "Plan" p ON p.id = s."planId";

-- Recent job runs
SELECT "jobName", status, "startedAt", "durationMs", error FROM "BackgroundJobRun" ORDER BY "startedAt" DESC LIMIT 20;

-- AI spend estimate (micro-dollars) for the last 30 days
SELECT SUM("estimatedCostMicros") / 1e6 AS usd FROM "AiRun" WHERE "startedAt" > NOW() - INTERVAL '30 days';
```

## Backups

Use Railway's PostgreSQL backups and, for portable exports, `pg_dump` against `DATABASE_URL` (see [HANDOVER.md](HANDOVER.md)). Files in the storage bucket are not part of the database dump; back them up separately with an S3-compatible CLI.
